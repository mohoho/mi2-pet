# 觅2 · Qoder 桌面宠物

把一组自己的画（5 个场景 GIF + 1 张特写静图 + 1 张表情包原图）编译成 **Qoder 桌宠包**（petdex v1 规格）：
一张 8 列 × 9 行的精灵图，装到 `~/.petdex/pets/mi2/` 就能在 Qoder 里跑起来。

![精灵图](dist/mi2/spritesheet.png)

- 在线预览：<https://mi2-pet-animations-e952iuq3fe9.qoder.website>
- 本地预览：直接用浏览器打开 `dist/index.html`（按运行时真实的帧数与延迟循环播放，可缩放、可看逐帧）

## 仓库结构

```
.
├── build_pet.py          生成精灵图 + 预览页（唯一的构建入口）
├── verify_pet.py         复刻 Qoder 桌面端的包校验规则，构建后跑一遍
├── assets/               素材
│   ├── 待机.gif 工作.gif 出错.gif review.gif 挥手.gif    五个整幅场景，各占一行
│   ├── 跳跃.png          蜂的大特写（只留蜂，旁边的书架抠掉），给左右跑和肌肉形态用
│   └── 01.png            表情包原图，等待那行由它做变换生成
└── dist/                 构建产物
    ├── index.html        动画预览页
    └── mi2/              宠物包本体（pet.json + spritesheet.png）
```

## 依赖

Python 3 + `numpy`、`Pillow`、`scipy`（只用 `scipy.ndimage`：泛洪、连通分量、卷积）。

```bash
pip install numpy pillow scipy
```

## 构建 · 校验 · 安装

```bash
python build_pet.py      # 产出 dist/mi2/{pet.json,spritesheet.png} 和 dist/index.html
python verify_pet.py     # 复刻桌面端的校验规则，必须「全部通过」

# 安装（Windows 下 ~ 指 C:\Users\<你>）
cp dist/mi2/{pet.json,spritesheet.png} ~/.petdex/pets/mi2/
```

**改完必须重启 Qoder 才生效**：精灵图只在启动时读一次。改了文件没重启，看到的还是旧动画。

## 包规格（由 Qoder 桌面端硬校验，不能随意改）

- 精灵图固定 **8 列**；`spriteVersionNumber: 1` 时 **9 行**（v2 是 11 行）
- `cellWidth = 宽/8`、`cellHeight = 高/9`，要求 `cellW ≥ 48`、`cellH ≥ 52`，且 **`cellW×13 == cellH×12`**（单元比例 12:13）
- 文件 ≤ 32 MB；`pet.json` ≤ 64 KB，其中 `id` 必须等于目录名，`displayName` 1..128 字符
- 包目录下 `spritesheet.png` 与 `spritesheet.webp` **只能存在一个**

本仓库取 `cellW=192`、`cellH=208`，精灵图 1536×1872。

| 行 | 名字 | 中文 | 帧数 | 每帧停留 ms |
|---|---|---|---|---|
| 0 | idle | 待机 | 6 | 280, 110, 110, 140, 140, 320 |
| 1 | runningRight | 向右跑 | 8 | 120×7, 220 |
| 2 | runningLeft | 向左跑 | 8 | 120×7, 220 |
| 3 | waving | 招手 | 4 | 140, 140, 140, 280 |
| 4 | jumping | 肌肉形态 | 5 | 140×4, 280 |
| 5 | failed | 出错 | 8 | 140×7, 240 |
| 6 | waiting | 等待 | 6 | 150×5, 260 |
| 7 | running | 干活中 | 6 | 120×5, 220 |
| 8 | review | 审查 | 6 | 150×5, 280 |

**每行的帧数和节奏是运行时写死的，包侧覆盖不了**：能改的只有像素内容。所以想让某个动作
「更明显」，唯一办法是加大**帧与帧之间的画面差异**——既不能加帧，也不能改延迟。没用到的列留透明即可。

触发关系：鼠标悬停 → `jumping`；拖拽 → `runningLeft` / `runningRight`；启动问候 2.6 s → `waving`；
Agent 干活 / 等待 / 出错 / 审查 → `running` / `waiting` / `failed` / `review`；其余时间 → `idle`。

## 每一行是怎么做的

静图行由原图做仿射变换（缩放 / 旋转 / 位移 / 残影）生成，变换在**预乘 alpha** 空间完成，
否则半透明边缘会渗黑边。GIF 行**原样取帧，不叠任何变换**——帧间差异本身就是动作，再叠一层只会变成抖。

| 行 | 底图 | 做法 |
|---|---|---|
| 待机 | `待机.gif` | 取 6 帧原样播（蜂抱着一条灰鱼趴着）。`待机.gif` 第 19 帧起换成了黑底数字钟，取帧时避开。 |
| 向右跑 / 向左跑 | `跳跃.png` 特写 | 两行互为水平翻转，叠 ±6° 摆动 + 行进方向后方的残影。幅面太宽，`ROW_SCALE` 乘 0.88 才不会蹭到邻格。 |
| 招手 | `挥手.gif` | 取 6 / 9 / 12 / 16 四帧：静止 → 抬左手 → 抬右手 → 静止。两端幅度对称（对静止帧差 8.1 / 10.1），首尾同帧所以循环处不跳。第 10、11 帧是手扫过镜头前的过渡帧（那只手大到糊住整张脸），必须避开。 |
| 肌肉形态 | `跳跃.png` 特写 | 只留蜂、去掉旁边的书架；靠 `sy` 做轻微呼吸式缩放。 |
| 出错 | `出错.gif` | 取 12, 16, 21, 24, 26, 28, 33, 38。这段 GIF 不是一整段连贯动作，而是**同一个循环重复了两遍**（桌前干活 → 被掀翻 → 摔趴），必须**在同一轮内**按时间递增取帧；跨轮取会播成「趴着 → 坐起来 → 趴着」来回跳。 |
| 等待 | `01.png` | 表情包原图 + 位移/旋转做待机小动作。 |
| 干活中 | `工作.gif` | 取 0, 8, 9, 10, 11, 12 原样播。场景本身逐像素静止，动的只有握笔的那只手。 |
| 审查 | `review.gif` | 取 4, 5, 6, 7, 8, 13——蜂把头**转过去之后**的几帧，正脸两帧和过渡帧都不要，这一行是刻意定格。 |

### 两个踩过的坑

**整幅场景行不要靠「整幅平移」造动感。** 平移的是画面而不是角色，一定被读成「画面在抖」。
「干活中」这一行为此返工过四次：位移从 5 px 压到 2.5 px、1.2 px，还是嫌抖，最后改成完全静止。

**「放大帧间差异」同样不行。** 完全静止之后又要求「手里的动作还是要的」，于是试过
`f' = f_ref + gain × (f_i − f_ref)`（只放大真的在动的部分，静止区域差异为 0、放大后逐像素不变）。
原理上没问题，但手和笔都是黑描边的高对比物体：**只要 gain > 1，描边就会被线性外推顶到纯黑或纯白**，
表现就是「手里的铅笔一下黑一下白」（gain=3 时动区内每帧约 6500 px 被削到 0/255，格内约 160 px）。
连加一次 σ=1.5 的模糊来压硬边都不行——模糊本身就会让差值超界（gain=1 时已削掉约 2300 px）。

**正确解法是原样播源帧。** 量一下就知道：`工作.gif` 六帧之间 99.9% 的变化落在
`x[810,975] y[460,680]` 这一小块（格内 26×35 px），盒外每帧只剩个位数像素。
也就是说「画面不抖」和「手里有动作」本来就同时成立，是加工把它毁掉的。

> 量的时候注意：判定变化范围要用 **2% / 98% 分位**，不要用 min/max——个位数的杂散像素
> 会把 bbox 拉到整幅画面，看着像「整个画面都在变」，从而误判成「必须自己造动作」。

## 素材与抠像

`工作.gif` / `待机.gif` / `出错.gif` 都是**整幅不透明**的场景（墙、桌椅、显示器全在画面里），
只把平涂的背景抠掉（桌椅、显示器、手枪这些有深色描边的物件全部保留）。抠像没用
「浅色阈值 + 泛洪」——墙多半是**抖动网点**打的，单点阈值会被噪点打断，泛洪走不动。
改成**从画框四边采样主色当调色板 + 颜色距离**：边框量化到 16 后占比 ≥1.5% 且 `max ≥ 120`
（排掉黑色描边）的颜色入板，距离 < 45 判为背景，最后只删「从四边能走到」的那部分——
这样被描边围住的同色区域（翅膀和墙是同一个色号）不会被误删。

`跳跃.png` 是**不透明特写**（蜂占满画幅、手臂顶到画框边），上面那套调色板法会失效：
手臂的黄色本身就在左边框上，会被当成背景连胳膊一起删掉。改用「亮且不饱和 + 从画框能走到」
定背景（同时捞掉米白底、柔光晕和书架那层灰；翅膀是纯白但被深色描边围住，灌不进去能留下），
剩下的像素按连通块判归属，只有黄/白算蜂自己的。

取景框取**所选帧前景的并集**：逐帧各算 bbox 会把亚像素抖动放大成跳动，而像 `出错.gif`
这种蜂会翻倒的，只用第 0 帧的框又会切掉探出头的部分。

场景行只能整幅缩放（`load_art(fit=True)` 按「装得进格子」反推比例），代价是画面越宽蜂越小：
`工作.gif` 1124 px 宽，缩进 192 后蜂只有 76 px，而特写各行是 117~122 px。这里选择了
**保留整幅场景、接受蜂变小**。
